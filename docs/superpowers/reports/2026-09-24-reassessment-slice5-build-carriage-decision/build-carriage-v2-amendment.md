# Proposed amendment: governed executable build v2

This proposal adds `governed-executable-build.v2`; it does not edit or reinterpret v1. The exact JSON Schema is `governed-executable-build-v2.schema.json` in this package. The v2 envelope is the v1 envelope with `schema = governed-executable-build.v2`, `implementation_id = bdw.governed-application.v2`, and the required property `application_source_inventory_sha256` replacing `application_source_sha256`. All other properties, requiredness and meanings remain those of v1. The v2 schema keeps `additionalProperties: false`.

`application_source_inventory_sha256` is the lowercase 64-character SHA-256 of canonical compact UTF-8 JSON, without trailing LF, encoding the complete lexicographically sorted object from every tracked `applications/` path to SHA-256 of its exact file bytes. The bound source work and serialized witness stay <=8,192 bytes. Source enumeration, path checks, dirty/untracked refusal, exact backend root, five public module digests, full lock and installed version checks, exact CPython 3.13 patch identity, policy digests, startup accounting and all numerical limits are retained.

The v2 contract source map has exactly these eight paths: `docs/superpowers/specs/2026-09-16-maintained-admissibility-enforcement-shared-reference-corrected-design.md`; `docs/superpowers/reports/2026-09-16-maintained-admissibility-amendment/AMENDMENT.md`; `docs/superpowers/reports/2026-09-16-maintained-admissibility-amendment/policy.json`; `docs/superpowers/reports/2026-09-16-maintained-admissibility-amendment/schemas.json`; `docs/superpowers/reports/2026-09-16-maintained-admissibility-consolidation/CONTRACT-AND-PLAN.md`; `docs/superpowers/reports/2026-09-16-maintained-admissibility-consolidation/build.schema.json`; this adopted v2 amendment; and the v2 schema. Neither new document embeds its own digest. Freeze both bytes, then bind their hashes from implementation constants.

Dispatch strictly by schema edition. V1 accepts only its unchanged full path map and matching historical v1 executable; v2 accepts only its independently reconstructed inventory root. Unknown editions and cross-edition verification/replay refuse. V1 computational replay requires exact historical checkout, contract/policy and interpreter/dependencies. A digest list alone cannot recover source: standalone recovery must restore the exact source Git bundle/tree and matching locked environment, then recompute each file digest and canonical root.

Expected tests cover changed, omitted and added source, canonical ordering, forged commitment, unknown edition, exact historical v1 verify/replay and both directions of cross-edition refusal. Approval here would authorize only a future implementation/requalification proposal, not acceptance.
