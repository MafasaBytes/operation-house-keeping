## Reporting protocol proposal

The pytest plugin is memory-only during test phases. Before launch, the parent creates and maps a bounded anonymous shared-memory ring; the plugin records bounded `{node id, phase, outcome, duration, diagnostic}` events into a preallocated bounded queue and performs no open/read/write/fsync/rename/network calls inside hooks or while test fixtures execute. The external parent polls the shared-memory ring; it is the only process that writes report files. No descriptor writes, opens, sockets, syscalls or filesystem calls are made by pytest hooks. The recorder buffers phase events, then durably appends a node record only after teardown has completed; interrupted/incomplete protocols are labeled started-without-outcome. Session XML/summary is generated from those retained events by the external recorder after pytest has exited, never by a pytest finalizer.

Before every test/application launch, an append-only durable reservation records the maximum permitted bytes, files, directories, physical allocation, category, expected outputs and slot id. The parent verifies category, aggregate, per-file, directory, physical and filesystem headroom, fsyncs the reservation, then launches. Every external recorder write consumes that reservation. If a finite maximum cannot be established, refuse before launch. Queue saturation or recorder failure stops new launches and preserves the precise incomplete state. No retry follows automatically.

The ring uses fixed-size slots, monotone sequence numbers and a finite diagnostic truncation rule that marks truncation explicitly. Parent acknowledgment controls slot reuse; if the ring fills or the parent fails, stop the child at the protocol boundary and preserve all retained events. The minter test continues to run with its no-I/O monkeypatches active; the recorder neither invokes the minter's patched operations nor suppresses its assertions. Capacity reservation is a ceiling, not proof of enforcement. Periodic sampling and between-test scans observe retained totals; they are not syscall-level write enforcement. The protocol does not patch, wrap, replace or call any side-effect function inside the test. In particular it does not open paths from `pytest_runtest_logreport`; the intentional no-I/O test sees its patched functions untouched by reporting. The only channel is an already-open descriptor owned by the parent, with the parent doing file I/O outside test code. Review the precise plugin event ordering and prove no callbacks write during setup/call/teardown before implementation approval.
