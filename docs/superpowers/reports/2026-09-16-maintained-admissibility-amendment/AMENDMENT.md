`governed-trace.v2`, `governed-accounting.v2`, `governed-closure.v2` and

### Scoped schedule (normative; mechanically enumerated in measurements.json)

1. Bound physical reads, JSON framing and object counts before expanding data.
   Charge every supplied copy; digest deduplication does not refund capture. Walk
   required typed edges in approved phase order and canonical field/index order;
   declarations and scenarios require only their approved immediate-parent scope,
   while selected comparisons require complete retained replay closure. Opaque
   basis content is inert, not traversable JSON authority.
2. Count each distinct intrinsic object once per required validation scope. Each
   incoming edge still checks type, role, digest, scope and contextual bindings.
   A target on the active path rejects; a completed matching scope permits sharing.
   Count manifest file entries and closure-recipe member/typed references too,
   not just `{kind,sha256}` objects. Duplicate supplied occurrences count separately.
3. For each edge, reserve node units `nodes(source)+nodes(target)+2`, and byte units
   `canonical_bytes(source)+canonical_bytes(target)+66`. This is a conservative
   logical scan charge, not a claim about machine instructions. Recipe source means
   the recipe body; its target is the recovered original. Hash/role/context checks
   remain mandatory even when intrinsic parsing was reusable.
4. Per nominated/historical invocation, reserve two complete current/template-Q
   node/byte scans for W/F derivation, the full I/S/D/A/(T) envelope join scan, and
   the entire D.pairs scan, with no favorable early-hit refund. The exact per-context
   terms are retained. W0/D1-X/D2-X membership/join node units are 2,290/2,294/2,308.
   Required predicates remain the approved exact pin/build, Q/B, D/S/A/T, lineage,
   applicability, fixed-key and enumerated-pair checks; counting does not replace them.
5. Charge every current/ancestor lower reconstruction at full existing formula:
   Q/B nodes + lower reference occurrences + admission lookups + public validator
   rows. A separate template Q/B validation is also charged unless its identical
   full scope was already validated. No template projection or decision rows are
   invented. Three-world D2-X already contains template W0. J1 standalone and three
   of the four-pair nominations pay an extra template context: 7,898, not 3,949.
   Stricter/different validation scope cannot reuse a weaker completed check.
6. Recover each required prior's complete seven files, validate lengths/hashes and
   charge their entire reconstructed bytes and JSON node serialization work, even
   when immutable objects are shared. D2-X reconstructs 237,122+292,814=529,936
   prior bytes. This is distinct from its single captured prior and from lower C.
   Extra visits/expansions/reconstructions are charged before work, never erased by
   saving elsewhere. Successful R contains deterministic required totals, not cache
   savings. Refusal records only the performed prefix, not fictitious full work.
7. Bound rows/nodes while constructing R/trace, before adding the next slot; bound
   bytes before appending. Reserve the entire permitted publication envelope before
   output work, including build, manifest and physical report. No unbounded buffer
   followed by a size check, dropped prior, partial success or recursive refusal
   serialization. Existing bounded terminal fallback and durability exclusions remain.

### Complete retention, not digest-only recovery

Each prepared bundle has six payloads plus manifest. Current input closure stores
canonical typed objects once; canonical serialization reconstructs their exact
original bytes. Opaque basis can use bounded base64 chunks. Prior resolved files
use `closure-table-recipe.v1`: exact invocation, pin, sorted full member list and
W/F witness recipes. Recursively reconstruct the original complete container and
verify its original hash and length. A recipe is **not** permission to omit any
prior input/output. The supplied table plus recipe, not a floating hash lookup,
recovers all bytes. W/F witnesses likewise carry recipe/version, retained Q and
commitments and are recomputed, never trusted as cached permission.

Representative D2-X totals: 504-byte invocation, 84,979-byte snapshot,
212,695-byte resolved container, 22,035-byte R, 21,032-byte trace, build witness
and 2,201-byte manifest: 343,741 bytes. The 381,624-byte planning envelope reserves
8,192 for build in both its file and captured object table, 8,192 for each of the
three current/prior physical reports, and 256 bytes/context for counter/length
digit growth. It assumes the same object/schema topology; any topology change
requires remeasurement. Every independent work/byte/node guard must still pass.

The synthetic build and representative physical assignments are **preparation
values**, not actual executable identity or measured work. A complete hypothetical
physical report is used to measure schema overhead, with outer witness status
`prepared_not_executed`; its `observed:true` is an expected runtime field, not a
claim this turn observed a run. Actual build and prior physical manifests must be
bound later, renewing dependent I/R/trace/manifest commitments. This is unavoidable
pre-execution binding, not permission to waive any guard.

## U — Unavailable-value comparison contract

Preserve 23 rows and the old typed `value`/dependency-review meaning. Add to each
row `assessment={availability,status,diagnostics,numeric_kind,numeric_value}` and
five flags: `availability_changed,status_changed,diagnostics_changed,
numeric_comparable,numeric_value_changed`. Numeric kinds are none,
degree_celsius_interval or supplied_cost (the retained profile fixes the cost
token to synthetic_scalar). Diagnostics are bounded ordered records
`{source,id,reason}` with source gate/current_condition/observed/premise.

Reuse `performed` for whether that row's assessment ran; `computed` means its typed
decision value is available, not that arithmetic ran. Current match unavailable:
performed=true, computed=false, value=null. Raw unknown: performed/computed=true,
typed raw_status/interval object retained, but numeric_value=null. Gate-blocked:
performed/computed=false, value=null, availability=blocked and exact blocked_reason.
Gate/target/feasibility/current-match rows are categorical: numeric_kind=none.
Selection has a numeric value only when a minimum was calculated; no-feasible is a
completed status, not an unavailable number or a gate refusal.

Diagnostics are taken from the row's direct assessment and dependency frontiers:
gate reason; current serialized refusal list in source order (id identifies list
position); raw public observation reason or unavailable/false premise frontier.
Target/feasibility/selection propagate the relevant dependency diagnostics plus
their own policy frontiers, in dependency order, deduplicating identical complete
records only. Thus changed reasons remain visible even when raw_status is still
unknown. Changing diagnostic records is a supported-data change requiring review,
not a new conflict-resolution or physical-diagnosis capability.

Let N mean a calculated numeric value exists, E an assessment occurred, and R a
required review derived from changed old/current support unions and dependency
edges. R is independent of outcome equality; E is not inferred from R. For numeric
rows with assessments on both sides:

| Before → after | Required review | E after | Numeric comparable | Availability changed | Status / diagnostics changed | Numeric value changed |
| --- | --- | --- | --- | --- | --- | --- |
| available → available, equal number | dependency rule; can be required | true | true, matching kind/unit | false | compare explicitly | false |
| available → available, different number | required (otherwise correctness defect) | true | true | false | compare explicitly | true |
| available → unavailable | required | true | false | true | compare explicitly | null |
| unavailable → available | required | true | false | true | compare explicitly | null |
| unavailable → unavailable, same reason | dependency rule; can be required | true | false | false | compare explicitly; may both be false | null |
| unavailable → unavailable, changed reason | required | true | false | false | diagnostics=true; status may stay equal | null |

Without prior all change flags are null and numeric_comparable=false. With a
blocked side numeric_comparable=false and numeric_value_changed=null; the blocked
current assessment has E=false. Assessment availability/status/diagnostic flags
can still describe the represented blocked transition. Technical refusal publishes
zero rows; it does not fabricate a blocked-row comparison. Permission=false on a
completed gate still emits 23 slots, with 21 blocked numerical/policy slots.

`value_changed` remains **typed-value** comparison when both values are computed;
otherwise null. `equal_after_reevaluation` applies only to a required, performed,
typed-comparable review. Two assessed unknown raw statuses may have equal typed
values but **never** thereby equal numeric values: numeric_comparable=false and
numeric_value_changed=null are mandatory. No comparable number means no assertion
that the number stayed unchanged. A changed assessment/diagnostic component with
no governing required review is a correctness error, even if typed value is equal.

schemas.json closes result, trace, rows, lower value forms, diagnostics, receipts,
work reports, manifest and closure recipes; its relational clauses are normative
alongside JSON shape checks. Lower Q/B still require their pinned public contracts.
Order correction to the preceding decision: maintained action order is
**a0,aF,aH,aHF**, not a0,aH,aF,aHF. This candidate preserves actual maintained order;
the old decision bytes are not rewritten. Existing ties include all qualifying IDs.

## P — Replay-stable versus physical work evidence

Replay equality includes exact R/trace, all row values/flags/diagnostics, captured
authority and deterministic logical accounting for the **same captured I and policy**.
It excludes the current operation's actual-work/cache counters and publication
metadata, not their retention or enforcement. It does not claim different I values
that select different full prior manifests have identical result commitments.

`physical-work.v1` is inside manifest.run_metadata: logical-accounting commitment,
actual/extra/charged maps, cache_hits, output_reserved_bytes, coverage and check
status. Complete map fields are closed in the schema. For every charged dimension,
`charged = logical minimum + sum(per-scope positive extra work)`. Saved work never
offsets another scope's excess. Check charged against the effective ceiling before
the next operation; actual aggregate work cannot exceed charged. Cache hits still
pay their incoming role/context checks and mandated lower reconstruction charges.

The report covers through payload construction, with manifest publication prepaid
inside output_reserved_bytes. It cannot attest its own future writes/fsync outcome.
Completion receipt is withheld until successful publication; later failure uses
the bounded terminal error and preserves visible evidence. Refused pre-publication
requests have no promised semantic bundle or physical report; do not claim an
unretained prefix was observed. Later acceptance must instrument refused prefixes.

The manifest commits the physical report and all payload hashes. Verify checks
bounded shape, integrity and charge arithmetic; semantic replay additionally
rederives logical counts and checks old and new work evidence against their own
captured policy. Equal R/trace alone cannot turn invalid/over-budget physical work
into replay success. Changed physical evidence is allowed only in a new correctly
committed operation manifest. Old evidence remains exact. Local instrumentation
is an application enforcement witness, not cryptographic authentication of a person
or proof of host CPU consumption; its correctness needs later implementation tests.

## Uncertainty and one owner gate

Physical actual counts/cache behavior, executable build bytes, latency/RSS and
enforcement implementation remain unmeasured. The reserved byte envelope is not a
claim that every combination of individually maximal resources succeeds. Actual
build/physical-prior binding must remeasure all scopes; if it exceeds a proposed
ceiling, stop rather than increase limits or replace semantic coverage with refusal.
The nine witnesses are minimal amendment coverage, not a claim of full application
acceptance coverage. No operational policy was changed.

**Single gate:** approve or reject the exact amendment identified by MANIFEST.json,
including all proposed numbers, the new comparison fields/truth table, deterministic
scope schedule, lossless retention recipes and independently retained/checked
physical work evidence. Approval would accept this amendment design only; separately
scoped implementation and later execution remain unauthorized until explicitly
granted. No backend change, general rule engine, authentication service or reduced
domain is proposed. C remains unresolved/dossier-only; F historical/analytical;
IN-001 and CI-001 remain open/unselected; all empirical/platform/durability exclusions
and existing evidence/runtime results are preserved.
