# Prepared measurement contract, version 1

Status: proposed exact preparation package; semantic choices approved by the owner on 2026-09-19. Numerical policy and this exact delivery package still require approval. These files are preparation tools/data, not a maintained selector. The complete frozen candidate in `frozen/semantic-candidate.md` is normative for semantics, including its §§2–6 validation order. Its historical pending-approval language is superseded only by the owner's latest instruction. Nothing here changes the frozen documents.

## Closed inputs and joins

The candidate's tables are the complete closed input grammar: E, H, O, P, S, K, Q, D, A, T, I; all mandatory fields, null rules, condition variants, qualification variants and typed edges apply unchanged. `contract-catalog.json` records their exact field sets and representative nested structure for wire review. It is descriptive, not an implemented validator. Public nested shapes are owned by the retained `public/state-classification.schema.json` and current public contracts; their validators still supply semantic checks beyond JSON Schema. No generic JSON object, caller matrix, score, evaluator callback or equation is an accepted escape hatch.

Preparation fixes LocalId/scenario label/condition/outcome IDs to `[A-Za-z0-9][A-Za-z0-9_.-]*`, 1–64 ASCII bytes. Public anchors/context/time/tokens keep their public grammar. Descriptive strings may be empty unless the frozen candidate requires substantive support, and obey proposed byte ceilings. Integers are strict JSON integers, never booleans. Rational numerators are `0` or `-?[1-9][0-9]*`, denominators `[1-9][0-9]*`, in lowest terms; zero is `0/1`. States are strings `true`, `false`, `unknown`; they are not JSON booleans. Canonical JSON is UTF-8, sorted keys, compact separators, no LF/BOM/nonfinite numbers/duplicate keys; output streams alone append one LF.

All hashes identify full canonical bytes (opaque basis hashes identify exact raw bytes). Refs are exactly `{kind,sha256}`. Nomination IDs are case-sensitive and unique within each H/P namespace separately; no revision co-nomination, repair, case folding, deduplication or alias manufacturing. S ordering is resolved `(id,revision)`; D request refs and basis-ref lists use `(kind,sha256)` order, with exact duplicates rejected within those lists. Repeated edges in different fields/objects are legitimate. Conditions, requirements and decoder outcomes use ASCII IDs; code sets use ASCII values. Wire order is validated, not normalized. Error selection follows frozen nomination subcheck precedence before remaining phase-3 code/path order. Global same-kind/ID/revision different bytes is a phase-2 collision.

E, context, H/P/O identities bind every support row. Rehashed stale references still fail `SUPPORT_SUBJECT_MISMATCH`; valid twins supply explicitly new support. Local attestation selects premises, supplies synthetic prediction claims, or selects minimax policy in separate roles; none authenticates an issuer, validates an empirical model or permits acquisition. Positive-only sources never justify complement exclusions. Unavailable source assertions block all their row cells even alongside a known source. Qualified opposing contributions remain unresolved. No source priority, automatic C adjudication, cost/prior/probability, hypothesis/test generation or candidate pruning is allowed.

Every current nominated row, including a subsequently refuted H, must be complete before zero/one viable-H terminals. Initially empty H/M are technical errors, H first if both empty. One T1 with two viable H may recommend T1; one H with complete support needs no discrimination. All-excluded fully known rows refuse, rather than deleting an H. Successful-domain empty branches remain in results and do not assert physical impossibility.

## Closure, scope and deterministic work

I is the root; its A pin is also explicitly supplied outside object discovery. Every typed edge in the frozen closure table is required, including every D member Q, every ancestor through revision 1, every referenced basis, and fixed-role build/policy witnesses. No URI/latest lookup. Public custody digests and opaque basis text are not application edges. Only declared required content is captured; optional old results/adoptions/dossiers are not needed or claimed recoverable. No terminal ancestor witness exists.

Resolution maps an exact ref to exactly one byte string; identical physical copies may be coalesced for storage after accounting for all bytes actually read. Conflicting copies refuse. Traverse bounded iterative DFS, ASCII field paths and array positions, resource guard before each operation, role/hash/header/lineage checks before active-path cycle checks. Completed intrinsic validation may be shared only in an identical scope; every incoming edge is charged and context/effective-limit checks recur. A shared DAG is not a cycle. Refusal is the first reached phase-2 failure, not an unlimited global scan for a preferred error.

Every Q's shape, unique nominations, aliases, exact joins, decoder integrity and public reconstruction is checked. Historical applicability/support availability/consistency/scoring is not evaluated: unknown historical S does not withhold a complete current Q, but malformed historical O or missing basis refuses. Revisions in separate Qs may legitimately share a logical ID; current result maps resolve only current exact references.

Logical accounting is deterministic and separated from physical I/O. `measurements.json` reports unique graph size and reference occurrences; it is **not** measured runtime traversal. `resource-detail.json` additionally counts per-Q scoped expansion demand, repeated contextual byte/node scans, rational/decoder work, all source contributions, current cell/condition/check demand and output recovery. For a conservative no-cross-Q-reconstruction-cache implementation, the proposed accounting contract charges each public E once per referring Q context, all required object/edge checks once per `(object,Q-context)` validation scope, and each incoming occurrence even at completed targets. Build identity fixes the caching/accounting strategy; changing that strategy requires a new build, not a silent expected-count edit. Physical reads may differ and are never used to waive logical guards. No result from preparation demonstrates implementation capacity.

## Result and trace wire

`nm.result.v1` has exactly `schema,profile,invocation,authority,evidence,procedure_assessments,hypothesis_assessments,cells,ranking,review,accounting`. Every section is closed and has `assessment_state`; concrete field layouts and primitive types appear in `contract-catalog.json` and all frozen expected result files. An unassessed section preserves syntactic identity maps but has no fabricated assessment rows. Scalar availability is established in public reconstruction before permission; it does not claim downstream evaluation. Assessment-state values are `assessed` or `not_assessed_` followed by the precise gate/baseline/applicability/disposition reason.

Authority includes exact selection/declaration/adoption/request/policy refs, permission state and boolean. Permission unknown means boolean false, not a malformed or missing A. Evidence includes E ref, admitted/unavailable status, exact reduced rational/null, CN verdict/null, and lower reason code/path records. Procedure assessments include P identity map and every reached condition with state, basis, observed operand and threshold. H assessments include exact H identity map, viable IDs or null and every reached expected/actual baseline check. Cells include all reached H/P/O/outcome coordinates, relation, exact reasons and all row source refs; those refs recover source-level qualification/contributions. Conflicting or unresolved cells have relation `unknown`. No S is silently ignored.

Ranking includes assessment state, primary disposition, all reached reasons, scores, best, recommendation, labeled branches and equivalence. Withheld scores/best/branches/equivalence are null, never rankings of a convenient subset. Reasons retain lower codes/paths and all assessed causes; order is phase, P ID, H ID, outcome, condition, code, source digest. Missing and conflicting causes coexist; primary conflict takes precedence only after mapping is reached. Gate/inapplicability withholding has zero mapping, not searched hidden conflicts.

Rankable results use `worst=max(|survivors|)` and `reduction=|viable H|-worst`; all minimizers are best. Unique positive-reduction best alone gets a recommendation. Equal worst scores do not imply multiset equivalence. Labeled branches are P/outcome ordered. Survivor arrays sort unique current H IDs; the multiset copies those arrays, lexicographically sorts by elements with shorter prefix first, and retains every duplicate and empty array. Cross-request comparison requires identical exact H maps/viable refs, not matching ID spelling. Review reports the seven dependency groups and `comparison=not_requested`; no automated comparison command is added.

Accounting has `assessment_state,logical_required,physical`. Logical fields in prepared files explicitly denote statically required graph/input quantities, not work observed on failed paths. `physical` is the literal `not_part_of_semantic_result`. `nm.trace.v1` has `schema,profile,invocation,origin,required_closure,reference_occurrences,phases,semantic_origin,physical_observed`; member order is `(kind,sha256)`, occurrence order is deterministic DFS. The prepared trace origin is `independent_prepared_expectation`; phase state is expected, not observed. Phase 8 includes completed disposition/publication and does not imply ranking arithmetic was performed. Future runtime traces must use a distinct observed origin and recorded phase states; comparison uses the specified semantic fields, not a false equality between observation provenance and expected provenance. Exact runtime phase work must match the expected assessed/blocked paths. No runtime test is claimed here.

## Diagnostics and precedence

`nm.diagnostic.v1` has exactly `schema,code,stage,target,resource,retry,bundle_state,message_key`. Target is `{request,field,logical_id,references,occurrence_count}`: request ref or null; field is a bounded JSON-pointer-like semantic path (including `/required_closure`); IDs/count nullable; refs sorted and preserve duplicate occurrences where needed. The resource member is null or `{dimension,attempted,limit}`. Stage is `phase_1`…`phase_8`, `usage`, `path`, `retention`, or `internal`. Exact coordinates/refs are retained whenever safely available. Oversized diagnostics use a reserved bounded `DIAGNOSTIC_LIMIT_EXCEEDED` envelope with null target details; they never truncate into a different original reason. This is a technical resource refusal, not a completed withholding result.

The catalog includes every fixture code plus generic wire, kind, canonicalization, qualification, public reconstruction, build/policy, path, retention, replay and internal codes. Earliest phase wins, then frozen precedence. Codes do not conceal public lower reasons: public reconstruction failures carry owning error type/path in a bounded retained failure detail only if safely capturable, and the technical diagnostic identifies E; unavailable valid public evidence uses a completed result instead. The exact translation is PUBLIC_RECONSTRUCTION_INVALID for owning validation errors, EVIDENCE_JOIN_MISMATCH for post-reconstruction binding mismatch, and INTERNAL_ERROR for unexpected exceptions. No unbounded exception string enters stderr.

Exit 0 is a completed semantic disposition, including denial/unknown/withholding; it is not permission or a recommendation. Usage 2; input/integrity/profile/alias/row 3; resource 4; path 5; retention 6; internal 7. Refusals have empty stdout and exactly one canonical JSON diagnostic plus LF on stderr, no result/manifest. Partial publication reports `incomplete`; no cleanup/resume/overwrite is inferred. This corpus fixes exact diagnostics for its listed refusal cases; environment/fault-path obligations remain specified future delivery controls.

## Proposed command and retained delivery contract

Entry point remains `python -m applications.bounded_decision_workflow` in the separately approved exact environment. Add only:

* `measurement-evaluate --invocation FILE --objects-dir DIR --authority-pin SHA --output-dir NEWDIR [--limits FILE]`
* `measurement-verify --bundle DIR`
* `measurement-replay --bundle DIR --output-dir NEWDIR [--limits FILE]`

Reject repeated flags, abbreviation, unknown flags, missing values and compare-to at these endpoints. No bypass/matrix flag exists. `--limits` is a canonical partial map of known policy counter names to positive integer ceilings, each no larger than build policy. It may only tighten. Captured effective limits must replay with the same or stricter ceilings; a stricter ceiling may refuse but cannot yield a different partial result. `--authority-pin` is mandatory and exactly equals I.selection.sha256. No default authority discovery. File paths stay outside semantic objects/results. Object filenames are `<sha256>.<kind>`; only required filenames are opened with existing safe local no-symlink/regular-file/root-containment behavior. No unreferenced directory enumeration or fallback to another object.

`inputs/*/capture.json` is a **preparation transport**, not a production CLI input. Recover its exact member bytes into an isolated objects directory and its I into the invocation path; omitted/tampered cases must remain omitted/tampered even though the complete package contains valid twins elsewhere. Never populate a negative test from the global union of objects. `command-matrix.json` records precise argv templates and file/pin bindings, including how caller-tightened limits apply. All are planned, zero commands executed.

Evaluate/replay publish exactly seven files: `invocation.json,closure.json,result.json,trace.json,build.json,policy.json,manifest.json`. Closure contains the invocation ref, external pin, effective limits override, sorted refs and exact base64 bytes; it is a canonical, self-contained transport of required objects, not hashes alone. Build/policy are repeated externally for inspection and hash-equal to their closure copies; their duplicate physical bytes count. Manifest is last, lists the other six files with exact size/hash, plus fresh physical counters. Existing paths refuse; failure before manifest leaves an explicitly incomplete directory. A complete manifest does not claim crash/power-loss durability or a new filesystem qualification.

Verify reads only a complete bundle and checks names, canonical bytes, every file commitment and every recoverable closure byte, build/policy identity and required completeness; it does not assert a newly executed recommendation. Replay repeats the complete bounded validation and current-Q computation in the captured matching build/environment, retains fresh work evidence, and compares semantic result/trace fields. A verify receipt never substitutes for replay. Missing required ancestry refuses even after prior verification. No latest authority, live store, network, previous result bundle or optional dossier is consulted. No present-day adoption is asserted by historical replay.

`nm.receipt.v1` is exactly `{schema,operation,evaluation_permitted,disposition,result_sha256,bundle_sha256}`; operation is the explicit command. Exit-0 stdout is this canonical JSON+LF and stderr empty. Verify reports the stored result's permission/disposition as retained facts; it does not grant them anew. Runtime bundle SHA changes with physical work evidence, so its receipt commitment is computed from the actual manifest; the prepared receipt commits to the explicitly prepared manifest. Replay's result digest must match same-build semantic result bytes; runtime trace provenance is compared using the explicit field projection above. These are intentional binding parameters, not claims of passing byte-identical runtime output.

Build witness **does not exist yet**. `nm.prepared-build.v1` is deliberately nonexecutable and must never be accepted by a production endpoint. After scoped implementation approval, the build gate creates `nm.build.v1` with exactly header plus `checkpoint,source_manifest,environment_manifest,entrypoint,contract_sha256,resource_policy_sha256`. Source manifest is sorted `{path,sha256,bytes}` for the exact import/source closure; environment manifest is exact Python/platform/installed-distribution versions and artifact hashes, retained with recoverable source/environment requirements. Entrypoint is the literal module above. This package retains the approved semantic sources, current evidence/source provenance and all fixture inputs; it does **not** claim to preserve a future executable or its environment. Rebinding I, traces, results and manifests to that future witness is a mechanical derived-package step, requiring an exact-package owner gate; no source premise or oracle table may change unnoticed.

The six current thermal/governed commands, limits, schemas, row interpretation and existing replay stay untouched. Measurement objects at a thermal endpoint receive the old endpoint's existing refusal vocabulary; thermal objects at a measurement endpoint receive a measurement profile/kind refusal. Do not route by heuristic shape, wrap measurement procedures as fixed action slots, reuse thermal cost policy, or enlarge `BUILD_LIMITS`. New measurement-only policy ownership is necessary because a complete measurement trace can exceed the old trace cap; it is not evidence that old limits should increase. No backend change is needed.

Byte ceilings apply before base64 decoding/allocation. The generic object string/key/depth/node limits apply to decoded typed JSON, not to a closure member’s base64 transport string. That string has a separately derived maximum `4*ceil(object_bytes/3)`; the entire closure and supplied capture have their own byte limits. Opaque basis bytes obey object/capture limits without being parsed as JSON. Public snapshots also retain the existing public-input structural guards (32 depth, 8192 nodes, 256-byte strings, 32 model records, 8 conditions/evaluations, 4 candidates per evaluation, 131072 bytes); no measurement envelope waives those guards. Rational inputs have 128 digits, and an individual cross-product may require 256 digits; operation reservations include those intermediates.

Exact prepared-to-observed trace binding: after rebinding the invocation/build, change only trace `origin` to `observed_execution`, `physical_observed` to true, and each phase state `expected_reached` to `assessed`; blocked phase states stay unchanged. Phase 8 records completion/publication, while ranking.assessment_state separately records whether ranking ran. Recompute trace and manifest commitments. Future proof must compare actual phase states and all remaining deterministic trace fields with that bound expectation, while physical counters remain freshly observed. These substitutions are fixed preparation bindings, not permission to modify reasons, closure members, branches or scores.

Dispatch applicability: after safe bounded lexical capture, a foreign or absent measurement schema/profile receives PROFILE_MISMATCH. Its other fields are not interpreted as measurement build/authority references, so absent measurement-only fields in a thermal request do not create competing build/join errors. For a correctly dispatched measurement I, the frozen phase ordering and same-phase diagnostic rules apply. Compatibility fixtures assume no earlier path/resource failure.
