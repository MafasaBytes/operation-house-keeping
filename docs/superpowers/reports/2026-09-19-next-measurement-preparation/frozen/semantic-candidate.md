## 2A. FR-M1 — nomination identity, ordering and diagnostics

Logical identity is `(kind,id)`, compared by exact ASCII bytes, case-sensitive, without Unicode folding, whitespace trimming or numeric interpretation. H IDs and P IDs form separate namespaces. **Every Q has unique logical H IDs in its hypotheses array and unique logical P IDs in its measurements array, independently of revision or digest.** This obligation applies separately to each current, ancestor or declaration-member Q. It is not a closure-wide ban on legitimate historical revisions.

Exact versioned identity remains `(kind,id,revision,sha256)`, verified from the captured header and bytes. Runtime joins use the complete typed reference `{kind,sha256}` and verified header, never logical ID equality alone. The existing same-kind/ID/revision/different-content `IDENTITY_VERSION_COLLISION` remains an earlier closure-integrity refusal. Two copies of identical captured bytes for legitimate shared references are not two nominations and are not a collision.

After phase-2 integrity checks, phase 3 begins with these ordered subchecks for each Q, before alias detection, prediction qualification or ranking:

1. Repeated identical typed reference in H or P nomination array: `DUPLICATE_NOMINATION_REFERENCE` (exit 3). Do not deduplicate it. Nomination count limits still apply at bounded schema preflight.
2. Different references resolving to the same logical H ID or same logical P ID: `DUPLICATE_NOMINATION_ID` (exit 3), including different revisions. This is not `SEMANTIC_ALIAS`: even genuinely different propositions cannot share that logical ID within one nomination.
3. H/P arrays must be ascending ASCII logical-ID order; wrong order refuses `NOMINATION_ORDER_INVALID` (exit 3). The existing S array remains ordered by resolved ID then revision and unique by exact reference; identity/version collision rules make that order unambiguous. Then apply existing semantic-alias and exact support-join checks.

Within each subcheck use canonical Q-reference order, field order `hypotheses` before `measurements`, then logical ID and exact-reference order. Diagnostics identify the offending Q reference and field, plus the duplicate logical ID (null if unavailable) and sorted involved exact refs under the future bounded diagnostic layout. Repeated exact-ref occurrences are identified as a duplicate count, not silently collapsed into success. Earlier resource/integrity failures retain precedence. These specific subchecks refine, and take precedence over, the former generic same-phase code sorting. No lower-layer or thermal diagnostic changes.

Q may nominate H1@revision2 instead of H1@revision1 in a **different** coherent Q revision (or different request ID). It cannot nominate both under H1. Renew all affected S refs and Q/D/A/T/I bindings; old support does not transfer on logical ID equality. A historical Q's H1@revision1 and the current Q's H1@revision2 may coexist in the retained closure. Each request has its own injective mapping. Comparing revisions means separately identified requests/results, not renaming an unchanged meaning to manufacture another hypothesis/procedure. Existing semantic-alias rejection still applies to distinct-ID copies of the same meaning.

Results carry `hypothesis_identity_map` and `procedure_identity_map` inside the respective assessment sections, each an ASCII-logical-ID-ordered array of exactly `{id,revision,reference}`. Each maps one nominated ID to its verified typed content reference, including contradicted hypotheses; gate-blocked assessments may retain these syntactic identity maps without claiming semantic work. Viable IDs, cell axes, branch members, scores/best/recommendation and diagnostics must resolve uniquely through the current request's maps. Each outcome ID is scoped to its exact procedure decoder; cells retain the P/O refs. Survivor cardinalities count distinct exact H identities, which now equal the lengths of the ID arrays. No cross-request multiset comparison uses ID strings alone: the existing same-retained-H-identity restriction means equal exact maps/viable references, not coincident names.

Canonical construction is permutation-invariant: independently build from different insertion/iteration orders, sort semantic sets as specified **before** producing canonical request bytes, and obtain identical Q bytes/digests and result serialization. Reordered on-wire nomination arrays are invalid; the reader must not repair them after hashing. Object capture/listing order does not change a valid reference closure or its semantic result; actual physical work may be separately reported. The uniqueness rule applies to nominated entities and to members of an individual survivor set, **not** to the multiset of outcome branches. Two outcomes with identical `["H1","H2"]` survivors remain two branches; repeated `[]` remains repeated.

## 6. Minimax, cardinality and canonical survivor representation

H means the viable subset of the explicitly nominated hypotheses; M means the **entire** nominated procedure set. For every successful decoder outcome o:

`S(m,o) = {h in H | mapped(h,m,o) = permits}`

`score(m) = max_o |S(m,o)|`; `reduction(m) = |H| - score(m)`.

`best = {m in M | score(m) is minimum over M}`. All complete rows have at least one permission. No probabilities, priors, entropy, action costs or secondary tie-break. These calculations are allowed only after complete admission/coverage, including nominated rows later contradicted by baseline facts.

| Cardinality / ranking condition | Disposition and content |
| --- | --- |
| Initially nominated H=0 | Technical `HYPOTHESIS_SET_EMPTY`, no successful empty-hypothesis result. Nominated H>2 is unsupported. |
| Initially nominated M=0 | Technical `MEASUREMENT_SET_EMPTY`, even if a hypothetical H count would be 0/1. M>2 unsupported. No minimum over an empty M. If both arrays empty, code ordering gives H error. |
| Complete admission, viable H=0 | `no_viable_hypotheses`; scores/best/branches/equivalence null, recommendation null; keep contradiction trace. |
| Complete admission, viable H=1; M=1 or 2 | `no_discrimination_needed`; same null ranking fields. One survivor is not proof of the correct diagnosis. |
| H=2, M=1 and score=1 | `preferred_within_supplied_set`; sole M recommended with reduction=1. No comparison to unnominated measurements is claimed. |
| H=2, M=1 and score=2 | `no_discriminating_measurement`; score=2, best contains the sole M, recommendation null. |
| H=2, M=2, positive best reduction and unique best | `preferred_within_supplied_set`; recommend that member only. |
| H=2, M=2, positive best reduction and multiple best | `tied_best_within_supplied_set`; preserve both, recommendation null. |
| Any admitted M count, best reduction=0 | `no_discriminating_measurement` precedes tie wording; preserve arithmetic best set and scores, recommendation null. |

This corrects ADV-01 in the frozen review: a newly authorized singleton `{T1}` with two retained viable H can discriminate and be recommended. The original `{T1,T2-inapplicable}` remains withheld. “One measurement” never triggers `no_discrimination_needed`. Missing matrix cells block the H=0/1 terminals as in accepted BRC/CP; cardinality does not excuse incomplete support.

Representation is deterministic and separates labeled branches from equivalence disclosure:

1. `branches` lists measurements in ASCII ID order and, within each, outcomes in ASCII ID order; each branch retains outcome ID and a unique ASCII-sorted array of hypothesis IDs. Empty array `[]` is retained. Per-Q logical-ID uniqueness, identity/version collisions and aliases were already checked under §2A; the result identity maps pin each label to exactly one revision/content reference.
2. For a measurement's **equivalence multiset**, remove outcome labels from a copy of its branches, then sort its hypothesis-ID arrays lexicographically by their elements: compare first unequal ASCII ID; if one array is a prefix, shorter first. Keep all duplicates and empty arrays. Do not sort JSON encodings as strings or convert to a set. Serialize the resulting array-of-arrays with §2 canonical JSON.
3. Equivalence compares these arrays under the same retained H identities; different scopes are not compared. `[[],["H1","H2"]]` differs from `[["H1","H2"],["H1","H2"]]`, although both worst scores are 2. A repeated empty branch remains repeated. Relabeling outcome tokens with unchanged partitions does not affect this disclosure; it still changes decoder identity and requires coherent support.

An empty survivor branch is an unexplained successful outcome under the nominated accounts, not physical impossibility. An explicit `other` permitted by both H contributes 2 and can destroy a formerly perfect split. Total decoder coverage is successful-domain coverage, not proof that all physical failures or causes were modeled.
